# Данные фабрики IDL: как собраны

Результат лежит в `content/shop/sources/idl/` (сведения) и в папке выгрузки на Mac
`~/Documents/dumskaya-export/images/shop/idl/` (файлы). В каталог сайта его переносит
`python3 scripts/shop/idl_enrich.py`.

Скрипты запускались в рабочей папке `~/work/idl` (Python 3, PyMuPDF, Pillow):

1. **Сайт фабрики** — страницы коллекций idl1987.it (ru/en/it) разобраны в браузере: тексты, подписи,
   ролики YouTube, адреса фото; фото скачаны (557 файлов, 163 МБ) в `site/img/<год>/<месяц>/…`,
   разбор — `site/img/site.json`.
2. **Каталоги** — `IDL-2024.pdf` (388 стр.) и `IDL-2025.pdf` (Novelties, 49 стр.) с сайта фабрики.
3. `tech.py` — технические страницы: ячейка товара по подписи-артикулу → чертёж с размерами и строки
   света. Страницы, где ячейка какого артикула, — `tech-pages-2024.json`, `tech-pages-2025.json`,
   поправки — `tech-pages-fix-2024.json`. Запуск по частям (страницы i % N == K):
   `python3 tech.py IDL-2024.pdf 2024 tech-pages-2024.json 0 1`.
   Текст берётся с флагом `TEXT_CLIP`: на многих страницах лист вложен несколько раз и обрезан «окнами»,
   без этого в слое текста оказываются подписи соседних ячеек.
4. `catphotos_index.py`, затем `catphotos.py 0 1` — фото товара со страницы каталога, где подписан один артикул
   (самая большая картинка страницы, до 2000 px).
5. `export.py` — раскладывает фото и чертежи в папку выгрузки и пишет сводный `idl-site.json`
   (его части — `site.json` и `tech.json` в `content/shop/sources/idl/`).

Проверено глазами по листам-превью: у 405 чертежей подпись в ячейке совпадает с артикулом.
Без своей ячейки в каталоге: 682/2, 682/130x44, 684/120 (Endless 2025), 655/1LG, 448/SPOT, 468/P;
606/10 и 606/16 нарисованы в ячейках 605/10 и 605/16.
