# dumskaya-design.com

Сайт студии DUMSKAYA DESIGN: статический сайт на [Astro](https://astro.build), пять языков (ru / ua / en / sk / de).
Тексты и настройки лежат в `content/`, шаблоны — в `src/`, всё для сервера — в `deploy/`.

## Повседневная работа

Правки вносит Claude в этом репозитории. Чтобы выложить их на сайт, на Mac:

```bash
cd ~/dumskaya-site      # папка с клоном репозитория
git pull
npm run deploy
```

`npm run deploy` готовит новые фото, собирает сайт, проверяет его (`npm run check`) и копирует
на сервер только изменённые файлы. Если поменялись редиректы или сервис заявок, один раз спросит пароль sudo.

Посмотреть сайт на сервере до переключения домена: `npm run tunnel` и открыть http://localhost:8088.

## Первый запуск на Mac

В Терминале на Mac (не на сервере):

```bash
cd ~/dumskaya-site && git fetch origin && git reset --hard origin/main && bash scripts/mac-setup.sh
```

`scripts/mac-setup.sh` при необходимости обновляет Node.js (нужен 22.19+) и запускает `npm run deploy`.
Первый раз фото обрабатываются долго (около 2 300 штук) и около 700 МБ уходит на сервер, потом — только новое.
Если клона ещё нет: `git clone https://github.com/SergiyTymoshenko/dumskaya-export.git ~/dumskaya-site`.

Нужны python3 и ssh-доступ `ssh eurox`.
Оригиналы фото берутся из `~/Documents/dumskaya-export/images` (другая папка: `IMAGES_DIR=... npm run deploy`).
Исправленные копии старых фото лежат там же в `images/fixed/` (в `images.json` — путь `images/fixed/<id>.png`),
сами оригиналы не трогаем. Если картинку заменили — имя файла в `image-names.json` меняется (например, `-v2`):
фото на сайте кешируются на год, под старым именем посетители увидели бы старую версию.

## Заявки с сайта и бот студии

Форма отправляет заявку на сервер (`deploy/lead_service.py`), он пишет её в `~/dumskaya/leads.jsonl`,
отправляет в Telegram-бот студии и на почту. В том же сервисе работает бот (`deploy/bot.py`) — внутренний
инструмент студии, данные в `~/dumskaya/bot.db`. Настройки — `~/dumskaya/lead.env` (образец
`deploy/lead.env.example`): токен бота, Telegram ID разработчика, почта. Настройка по шагам с Mac: `npm run leads`
(токен вводится на сервере и никуда не передаётся).

**Перевод сообщений заказчиков на русский** (`deploy/translate.py`): если сообщение в заявке не по-русски и не по-украински
(английский, словацкий, немецкий…), в боте под оригиналом — «Перевод на русский с английского: …»;
то же в письме. Получают все, кому идёт заявка, в том числе партнёры. Русские и украинские сообщения не переводятся (проверка
на месте, без обращения к сервису). Сервис — DeepL API Free (бесплатно до 500 000 знаков в месяц) или Claude API;
ключ вписывает мастер: с Mac `npm run translate` (проверяет ключ пробным переводом, перезапускает сервис и шлёт
пробную заявку на английском). Ключа нет или сервис не ответил — заявка приходит как раньше, без перевода
(при сбое — пометка «Перевести не получилось»).

Роли в боте:
- **разработчик** (`BOT_OWNER_ID`) — все уведомления, принимает пользователей, назначает дизайнеров;
- **дизайнер студии** — заявки с сайта, уведомления о заявках партнёрам, принимает пользователей (/users, /partners);
  за дизайнером закреплены **товары магазина студии** (товары без партнёра): заявки на них идут ему, разработчику —
  копия «передана: …». Дизайнер один — закрепляется сам; сменить — кнопка «🛒 Закрепить товары магазина»
  в карточке человека (/users, только у разработчика);
- **поставщик, изготовитель мебели, прораб, независимый подрядчик** — партнёры, привязаны к компании
  (частное лицо — кнопка «Без компании», компания с его именем). Людям компании приходят заявки на её товары;
- **сотрудник поставщика** — добавляет сам поставщик: /invite → одноразовая ссылка на 7 дней → сотрудник
  открывает её и жмёт «Старт» → поставщику приходит запрос «Принять / Отклонить». /team — список, закрыть доступ.
  Сотрудникам приходят заявки на товары компании, как и поставщику; студии — уведомление о каждом добавлении.

**Кнопки у разработчика и дизайнера:** под полем ввода — «👥 Пользователи», «🤝 Партнёры» и только у разработчика «🌐 Сайт»
(нажатие = команда /users, /partners, /site; /site — тоже только разработчику), слева от поля ввода — кнопка меню «Графики» (мини-приложение
со статистикой; пока сайт не на домене — обычное меню команд). Приходят один раз сообщением; когда человек перестаёт быть
разработчиком или дизайнером, кнопки убираются. Отметка «кнопки получены» ставится только после доставки (не доставилось —
бот попробует при следующем запуске), а разработчику после обновления бота приходит отчёт: кому сообщение о кнопках
доставлено, кому нет и почему (например, «бот заблокирован — пусть откроет бота и нажмёт «Перезапустить»»).

Доступ только по одобрению: человек нажимает «Старт», разработчику и дизайнерам приходит запрос с кнопками ролей
(для партнёра — выбрать или создать компанию). /users — список, смена роли, закрыть доступ (в том числе сотрудникам
поставщиков).

Товар партнёра в магазине: в `content/pages/ru/shop/<товар>.json` поле `"partner": <номер>` (номер — в /partners).
Кнопка «Узнать цену» передаёт артикул (TDD-…); при выкладке `scripts/build_shop.py` собирает
`deploy/shop-products.json` (артикул → название, партнёр). Заявка на такой товар уходит людям партнёра,
а разработчику и дизайнеру — уведомление «передана: …» (или «партнёр не подключён — передайте вручную»).

Проверка: `curl -s http://127.0.0.1:8095/api/lead/health`, журнал: `sudo journalctl -u dumskaya-lead -n 50`.

**Сторож сайта** (`deploy/site_monitor.py`, работает в том же сервисе, только в режиме live): раз в минуту
открывает https://dumskaya-design.com/ с сервера, как посетитель. 3 неудачи подряд — разработчику в бот
«🔴 Сайт не отвечает» с причиной и тем, что видно на сервере (Caddy не работает — значит, лежит и EuroExchange;
выкладка EuroExchange перезаписала Caddyfile; нет файлов сайта; кончилось место) и командой починки; раз в час —
напоминание; когда сайт снова отвечает — «🟢 Сайт снова работает». Сертификат HTTPS: меньше 14 дней до конца —
предупреждение раз в сутки. Команда `/site` в боте — состояние сейчас. Если сервер выключится целиком, этот
сторож молчит вместе с ним — для этого **сторож снаружи на GitHub** (`.github/workflows/site-watch.yml`,
`scripts/outside_watch.py`): примерно раз в 5 минут GitHub открывает сайт; не открывается ~10 минут — сообщение
от того же бота с пометкой, жив ли сам сервер (если жив — через ~30 минут: о коротком падении уже сообщил сторож
на сервере). Ничего не выкладывает. **Сейчас выключен** (включить: Actions → «Сторож сайта снаружи» → Enable workflow).
Нужен секрет репозитория `TELEGRAM_BOT_TOKEN` (Settings → Secrets and variables
→ Actions); проверка — Actions → «Сторож сайта снаружи» → Run workflow. GitHub выключает расписание, если
в репозитории 60 дней не было коммитов (пришлёт письмо) — тогда включить снова там же, в Actions.

**Посетители сайта** (`deploy/site_stats.py`, работает в том же сервисе, только в режиме live): считает посетителей
по журналу Caddy (`/var/log/caddy/dumskaya.log` и сжатые части рядом) — без скриптов слежения и без cookie,
сайт не замедляется, согласие не нужно. Посетитель — браузер (не робот, не предзагрузка), уникальность — IP + браузер
за день, только в памяти; за неделю — сумма по дням. **Сканеры, назвавшиеся браузером, отсеиваются** (`is_robot`):
кто запросил несуществующий адрес админки или служебного файла (`/login`, `/console`, `/dashboard`, `.env`, `wp-…` — список
`PROBE`, только при ответе 404) или открыл 10 страниц за 15 секунд — не посетитель ни в «1 час», ни в итогах
(в итогах дня — счётчик `bots`). Ещё роботом считается тот, кто **не загрузил ни оформления, ни фото** (`/_astro`, `/img`)
и **не прислал время на странице**: без заголовков перехода браузера (`Sec-Fetch-*`) — сразу, с ними — если через 30 минут
после последней страницы времени так и нет (вернувшийся посетитель берёт оформление из кэша, но время присылает).
Это правило действует только с момента, когда страницы начали присылать время (первая запись `times.jsonl`). При смене правил подсчёта (`STATS_VERSION`) дни, которые журнал ещё помнит, пересчитываются сами. Итоги дней — `~/dumskaya/stats/<дата>.json` (только цифры, без IP).
Статистика смотрится **только в графиках**: кнопка меню «Графики» слева от поля ввода (у разработчика и дизайнера) —
мини-приложение Telegram (`deploy/stats_app.html`, отдаёт сервис заявок по `/api/stats/app`), периоды
«1 час», «24 часа», 7 / 30 / 90 дней (выбранный запоминается на телефоне). Время в приложении — по часам телефона того, кто смотрит.
- **1 час** — каждый посетитель отдельно (заходы, где что-то происходило за последний час): страна, регион и город по IP,
  устройство, система, браузер, язык браузера, откуда пришёл (Referer, а без него — метки gclid, fbclid, utm_source),
  страницы по порядку со временем открытия и временем на каждой, нажатия на контакты и заявка — у той страницы, где были;
  «на сайте» — последнюю страницу ещё не закрыли; «ранее за сутки» — сколько было заходов до этого. Обновляется само раз в минуту.
  IP-адреса в приложение не отдаются. Строится на лету из журнала за сутки (`web_live`), ничего не сохраняет.
- **24 часа** — те же плитки и карточки, что у дней, но графики по часам (текущий час — полая точка) и сравнение
  с предыдущими сутками; посетители за сутки — без повторов (меньше суммы по часам).
- **7 / 30 / 90 дней** — посетители по дням, просмотры, заявки, нажатия, языки, источники, устройства, страницы,
  робот Google, 404, таблица.

Данные (`/api/stats/data?p=1h|24h|7|30|90`) — только по подписи Telegram от этого бота и только разработчику и дизайнеру.

**Время на странице:** тот же скрипт на страницах, что и для нажатий, при закрытии или сворачивании страницы отправляет,
сколько секунд она была на экране (`{t: "time", p, s}` на `/api/hit`, не больше 120 сообщений за 10 минут с адреса).
Сервис пишет его в `~/dumskaya/times.jsonl`: время, страница, секунды и **обезличенный ключ посетителя** — хеш
IP + браузера с солью сервера (`~/dumskaya/stats/secret`, с сервера не уходит), сам IP не пишется; хранится 90 дней,
как журнал (чистится раз в день). По ключу время связывается с просмотрами из журнала. Нажатия на контакты в `hits.jsonl`
тоже получают этот ключ. В «1 час» — время на каждой странице (нет сообщения — «≈» до открытия следующей), в 24 часа /
7 / 30 / 90 дней — плитка **«Среднее время на сайте»** (на посетителя, только по тем, чьи страницы прислали время;
страница дольше 30 минут считается за 30), строка в подсказке графика и **«в среднем … на странице»** у популярных
страниц (когда время по странице пришло хотя бы 3 раза). В итогах дня — `time_total`, `time_visitors`, `page_time`.

**Город по IP** (`deploy/geo.py`): база DB-IP «IP to City Lite» (CC BY 4.0, указано внизу «1 час») — файл
`~/dumskaya/geo/dbip-city-lite.mmdb` (~130 МБ) на самом сервере, адреса никуда не отправляются. Сервис скачивает
выпуск сам (~60 МБ раз в месяц, в первые дни месяца), проверяет и только потом подменяет; нет места или не скачалось —
работает со старой базой, повтор через 6 часов. Первый раз база появляется через минуту-две после запуска сервиса.
Страна — по-русски из базы, регионы и частые города — по-русски из `deploy/geo_names_ru.json` (остальные латиницей,
дописывать туда же). Проверка с сервера: `python3 ~/dumskaya/deploy/geo.py 8.8.8.8`, скачать сейчас — `--update`. Каждый день в 9:00 разработчику — одна строка за вчера (по понедельникам и за неделю) с кнопкой
«📈 Графики»; текстовых отчётов и команды /stats нет (решено 24.10.2026). Журнал открыт для чтения (`mode 0644`
в нашем файле Caddy, 10 частей по 10 МБ, старше 90 дней удаляются — `roll_keep_for 2160h`, так написано в политике
конфиденциальности); полный текстовый отчёт для проверки с сервера: `python3 ~/dumskaya/deploy/site_stats.py`.

**Нажатия на контакты:** скрипт на всех страницах (`src/layouts/Base.astro`, меньше 1 КБ) при нажатии на телефон, e-mail,
WhatsApp или Telegram отправляет `navigator.sendBeacon('/api/hit')` — тип и страницу; сервис заявок пишет их
в `~/dumskaya/hits.jsonl` (без IP; роботы, свои адреса и больше 20 нажатий за 10 минут с адреса не записываются).
В графиках — нажатия по типам и страницам, в «1 час» — у конкретного посетителя (это из памяти сервиса, без записи IP);
в Google Analytics (если принят cookie) — событие `contact_click`.

**Свои визиты не считаются:** в мини-приложении внизу — блок «Не считать нас в статистике» (только у разработчика;
дизайнеру он не показывается и сервер ему список не отдаёт): нажать дома на домашнем
Wi-Fi, и визиты с этого адреса (IPv4 — адрес, IPv6 — сеть /64) больше не попадают ни в посетителей, ни в заявки; в графиках
ни строкой, ни карточкой в «1 час» эти визиты в графиках не показываются (решено 24.10.2026). Кроме того, **адрес,
с которого разработчик или дизайнер открывает «Графики»**, сам считается своим на 3 часа до и после (IPv6 — сеть /64,
`~/dumskaya/stats/own_devices.json`, хранится 100 дней): так не видны свои визиты с телефона на мобильном интернете,
который в «Не считать нас» добавлять нельзя. Список — `~/dumskaya/stats/exclude.json`; после изменения дни, которые журнал
ещё помнит, пересчитываются. Сменился домашний адрес у провайдера — открыть графики дома и нажать ещё раз. Журнал открыт для чтения
(`mode 0644` в нашем файле Caddy, хранится 10 частей по 10 МБ); проверка с сервера: `python3 ~/dumskaya/deploy/site_stats.py`.

## Магазин: товары фабрик

Фабрики — `content/shop/manufacturers.json` (название, страна, контакты, **за каким партнёром закреплена**,
файл каталога). Каталог фабрики — `content/shop/catalog/<фабрика>.json`: коллекции (линия, дизайнер, отделки)
и товары (артикул сайта, артикул изготовителя, коллекция, тип, страницы каталога). Цен нет — «Узнать цену».

**Артикулы сайта** не совпадают с артикулами изготовителя и не выдают фабрику:
`DL-<тип><номер>` для света — `S` подвесной, `C` потолочный (встраиваемый, трековый, споты), `W` бра,
`T` настольная лампа, `F` торшер, `G` встраиваемый в пол / ландшафтный;
`DF-<тип><номер>` для мебели — `S` диваны, `A` кресла, кушетки, пуфы, `C` стулья, табуреты, скамьи,
`T` столы, письменные столы, консоли, `K` журнальные и прикроватные столики, `B` кровати, изголовья, матрасы,
`H` хранение (шкафы, стеллажи, комоды, буфеты, системы, мебель для ванной), `D` ковры, зеркала, ширмы, текстиль,
аксессуары, `E` кухни и кухонные модули.
Номер — четыре цифры, уникален по всему сайту (по телефону достаточно «1310»); у каждой фабрики свой диапазон:

| Фабрика | Номера |
|---|---|
| IDL 1987 | 1000–2999 (у коллекции блок из 50: DP — 1300–1349 …) |
| OLEV | 3000–3399 |
| Delta Light | 3400–4699 |
| Baxter | 5000–5599 |
| Flexform | 5600–6199 |
| Molteni&C | 6200–6799 |
| Maxalto | 6800–7099 |

Свободно для новых фабрик: 4700–4999, 7100 и дальше. Внутри диапазона номера идут по коллекциям (моделям),
внутри коллекции — по типу; свет мебельной фабрики — `DL-` с номером из её диапазона. Выданный артикул
не меняется (повторный импорт узнаёт товар по адресу у фабрики), новые товары — следующие свободные номера;
варианты отделки при необходимости — суффиксом `-01`, `-02`. Студийная мебель остаётся с артикулами `TDD-…`.

**Заявка на товар фабрики** уходит людям партнёра в боте (поставщик и его сотрудники), студии — копия
«передана: …»; в сообщении подсказка: изготовитель, его артикул и коллекция, а строкой ниже — **каталог
фабрики и страницы**: «Каталог: IDL 2024, стр. 85, 87, 91 (фото), 95 (чертёж и свет)», номер страницы —
ссылка на эту страницу PDF. Номера — как напечатаны в каталоге (у разворотов Novelties 2025 — «32–33»).
Поэтому у каждого товара фабрики хранятся каталог (`"catalog"`) и страницы (`"catalog_pages"`,
`tech.source.page` — техлист), а у каталога в `sources` — id, ссылка и копия PDF; так же — для новых фабрик.
Копии каталогов IDL — в папке выгрузки на Mac: `~/Documents/dumskaya-export/catalogs/idl/`.
Компания партнёра заводится в боте сама (по названию из `manufacturers.json`) — при приёме человека её
остаётся выбрать из списка.

## Включение домена

Когда DNS домена указывает на сервер (A `62.238.124.237`, AAAA `2a01:4f9:c015:6ee0::1`, www → CNAME на домен):

```bash
ssh -t eurox 'sudo bash ~/dumskaya/deploy/server-setup.sh live'
```

Caddy сам получит HTTPS-сертификат. Затем в Search Console отправить `https://dumskaya-design.com/sitemap.xml`.

## Если на сервере что-то пошло не так

```bash
ssh -t eurox 'sudo bash ~/dumskaya/deploy/server-doctor.sh'
```

Показывает состояние Caddy и причину ошибки, отключает сайт от Caddy (свою строку в Caddyfile и файл сайта)
и проверяет, что остальные сайты на сервере отвечают.

**Сосед по серверу — EuroExchange.** Основной `/etc/caddy/Caddyfile` принадлежит ему: его выкладка
(`/opt/eurox0003/deploy.sh`) перезаписывает файл целиком из репозитория eurox0003. Наш сайт подключается
строкой `import sites/*.caddy` в том Caddyfile (сайт — файл `/etc/caddy/sites/dumskaya.caddy`).
Если строки нет, `server-setup.sh` дописывает свою, а `npm run deploy` замечает пропажу и подключает сайт снова;
в конце выкладка проверяет, что https://dumskaya-design.com отвечает.

## Новый проект в портфолио

Фото (уменьшенные до 2400 px по длинной стороне, без EXIF) кладутся в `assets/photos/<проект>/` и попадают в git;
при выкладке `scripts/images.mjs` делает из них WebP. Для каждого фото — запись в `content/images.json`
(файл, размеры, описания ru/ua/en; на словацком и немецком описания фото берутся из памяти переводов),
имя файла на сайте — в `content/image-names.json`, помещение —
в `content/image-rooms.json` (порядок фото: гостиная-кухня, спальня, ванная, детская, постирочная, прихожая, санузлы).
**Имена файлов — описательные** (с октября 2026): исходники — `assets/photos/<город>-<площадь>m/01-living-room-kitchen.jpg`,
имя на сайте — что на фото, объект, город, номер: `living-room-kitchen-apartment-bratislava-127m-01`,
`floor-plan-apartment-bratislava-127m`; английские слова, латиница, через дефис, до 80 знаков, без имён заказчиков.
Уже выданные имена не меняются (по ним фото знает Google); `scripts/image_names.py` только дописывает имена
забытым новым фото (помещение по `image-rooms.json` + адрес страницы) и прежние не трогает.
Страница — `content/pages/ru/<адрес>.json` (тип `project`), карточка и «штамп» (объект, площадь, город, работы,
статус) — `content/projects.json`, первой в списке = первой в портфолио. Планировку с листа дизайн-проекта
показывает блок `{"type": "figure", "image": {...}, "caption": "..."}` — после текста, перед фото.
Листы технической документации — отдельная секция: заголовок «Пример технической документации, разработанной
в рамках дизайн-пакета «…»» и галерея с `"docs": true` (показывается после фото отдельным блоком под этим
заголовком; в `image-rooms.json` такие листы — `D`). Листы — целиком, PNG 2400 px; в штампе листа не должно быть
данных заказчика (имя, адрес).
Видео с YouTube — блок `{"type": "video", "youtube": "<id ролика>", "poster": "<id фото проекта>"}` сразу после
заголовка; превью — фото проекта, плеер (youtube-nocookie.com) загружается только по нажатию.
Товары магазина на странице — `{"type": "products", "items": ["/shop/...", ...]}` (русские адреса, на других
языках — те же товары на языке страницы).
Пример — квартира 127 м² в Братиславе (`assets/photos/bratislava-127m/`). Затем перевод (ниже) и выкладка.

## Переводы (UA, EN, SK, DE)

Тексты страниц пишутся на русском (`content/pages/ru/`), остальные версии собираются из них:
структура, фото и блоки те же, тексты — из памяти переводов `content/i18n/tm-{ua,en,sk,de}.json`
(русская строка → перевод), ссылки автоматически ведут на страницы того же языка.
Адреса, title и description украинских и английских страниц при сборке не меняются.

**Словацкая (`/sk`) и немецкая (`/de`, австрийский вариант) версии** — с 23.10.2026. Глоссарий, местные поисковые
формулировки и типографика — в `scripts/i18n/GUIDE.md`, шаблонные обороты SK/DE — в `content/TEXT_STYLE.md`.
- Какие страницы есть на SK/DE — решает `alternates.sk` / `alternates.de` у русской страницы. Не переведены
  (адресованы другим рынкам): посадочные Варшавы, Украины, США, Праги и Испании; страница «Германия» — только DE.
- Адреса, title и description — в `content/i18n/meta-sk.json` и `meta-de.json` (ключ — русский адрес; адрес — поисковая
  фраза на языке страницы: `/sk/dizajn-interieru-bratislava`, `/de/innenarchitekt-wien`). После правки этих файлов
  (или новой страницы) — `python3 scripts/i18n/apply_meta_new_langs.py` с файлами `{"/ru-адрес": {"path", "title",
  "description"}}`: проверит длины и адреса, проставит `alternates` русским страницам и проектам, создаст страницы
  магазина и меню SK/DE в `site.json`. Выданные адреса SK/DE не меняем — только через редирект.
- Ссылка на страницу, которой на этом языке нет, при сборке становится обычным текстом (кнопка и карточка — убираются).
- **Телефоны**: на словацких страницах — только +421 918 17 77 85, на немецких — только +43 677 614 30 187 (шапка,
  меню, подвал, «Контакты», тексты страниц, разметка). Номера в текстах заменяет `assemble.py`, проверяет `check_site.py`.
  Мессенджеры (WhatsApp, Telegram) — на словацком номере на всех языках.

После правки русских текстов:
```bash
python3 scripts/i18n/extract.py            # новые строки → пакеты i18n-work/<lang>-NN.json
# перевести пакеты (правила и глоссарий: scripts/i18n/GUIDE.md), ответы — i18n-work/out-<lang>-NN.json
python3 scripts/i18n/check_batch.py i18n-work/ua-01.json
python3 scripts/i18n/assemble.py --import   # добавить переводы в память и собрать страницы
for l in ua en sk de; do python3 scripts/i18n/check_tm.py $l; done
```
