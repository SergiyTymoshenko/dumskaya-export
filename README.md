# dumskaya-design.com

Сайт студии DUMSKAYA DESIGN: статический сайт на [Astro](https://astro.build), пять языков (ru / ua / en / sk / de).
Тексты и настройки лежат в `content/`, шаблоны — в `src/`, всё для сервера — в `deploy/`.

## Повседневная работа

Правки вносит Claude в этом репозитории. Чтобы выложить их на сайт, на Mac:

```bash
cd ~/dumskaya-site      # папка с клоном репозитория
git pull
npm run deploy
```

`npm run deploy` готовит новые фото, собирает сайт, проверяет его (`npm run check`) и копирует
на сервер только изменённые файлы. Если поменялись редиректы или сервис заявок, один раз спросит пароль sudo.

Посмотреть сайт на сервере до переключения домена: `npm run tunnel` и открыть http://localhost:8088.

Резервные копии делаются на сервере сами (7 дней) и приходят разработчику в Telegram — раздел «Резервные копии» ниже.

**Бот и «Студия» выкладываются вместе с сайтом, с Мака:** `npm run deploy` (решено 24.10.2026: автовыкладку
через GitHub попробовали и отказались — выкладываем по-старому).

## Первый запуск на Mac

В Терминале на Mac (не на сервере):

```bash
cd ~/dumskaya-site && git fetch origin && git reset --hard origin/main && bash scripts/mac-setup.sh
```

`scripts/mac-setup.sh` при необходимости обновляет Node.js (нужен 22.19+) и запускает `npm run deploy`.
Первый раз фото обрабатываются долго (около 2 300 штук) и около 700 МБ уходит на сервер, потом — только новое.
Если клона ещё нет: `git clone https://github.com/SergiyTymoshenko/dumskaya-export.git ~/dumskaya-site`.

Нужны python3 и ssh-доступ `ssh eurox`.
Оригиналы фото берутся из `~/Documents/dumskaya-export/images` (другая папка: `IMAGES_DIR=... npm run deploy`).
Исправленные копии старых фото лежат там же в `images/fixed/` (в `images.json` — путь `images/fixed/<id>.png`),
сами оригиналы не трогаем. Если картинку заменили — имя файла в `image-names.json` меняется (например, `-v2`):
фото на сайте кешируются на год, под старым именем посетители увидели бы старую версию.

## Заявки с сайта и бот студии

Форма отправляет заявку на сервер (`deploy/lead_service.py`), он пишет её в `~/dumskaya/leads.jsonl`,
отправляет в Telegram-бот студии и на почту. В том же сервисе работает бот (`deploy/bot.py`) — внутренний
инструмент студии, данные в `~/dumskaya/bot.db`. Настройки — `~/dumskaya/lead.env` (образец
`deploy/lead.env.example`): токен бота, Telegram ID разработчика, почта. Настройка по шагам с Mac: `npm run leads`
(токен вводится на сервере и никуда не передаётся).

**Перевод сообщений заказчиков на русский** (`deploy/translate.py`): если сообщение в заявке не по-русски и не по-украински
(английский, словацкий, немецкий…), в боте под оригиналом — «Перевод на русский с английского: …»;
то же в письме. Получают все, кому идёт заявка, в том числе партнёры. Русские и украинские сообщения не переводятся (проверка
на месте, без обращения к сервису). Сервис — DeepL API Free (бесплатно до 500 000 знаков в месяц) или Claude API;
ключ вписывает мастер: с Mac `npm run translate` (проверяет ключ пробным переводом, перезапускает сервис и шлёт
пробную заявку на английском). Ключа нет или сервис не ответил — заявка приходит как раньше, без перевода
(при сбое — пометка «Перевести не получилось»).

Роли в боте:
- **разработчик** (`BOT_OWNER_ID`) — запросы доступа, сайт (графики, «сайт не отвечает», сводка в 9:00), ошибки и выкладки;
  принимает пользователей, назначает дизайнеров. **Заявки с сайта разработчику не приходят** (решено 24.10.2026) —
  только если дизайнеру бот не смог их доставить: «⚠️ Не доставлено: Ирина — передайте заявку сами» (`notify_leads`);
- **дизайнер студии** — заявки с сайта, уведомления о заявках партнёрам, принимает пользователей (/users, /partners);
  за дизайнером закреплены **товары магазина студии** (товары без партнёра): заявки на них идут ему.
  Дизайнер один — закрепляется сам; сменить — кнопка «🛒 Закрепить товары магазина»
  в карточке человека (/users, только у разработчика);
- **поставщик, изготовитель мебели, прораб, независимый подрядчик** — партнёры, привязаны к компании
  (частное лицо — кнопка «Без компании», компания с его именем). Людям компании приходят заявки на её товары;
- **сотрудник поставщика** — добавляет сам поставщик: /invite → одноразовая ссылка на 7 дней → сотрудник
  открывает её и жмёт «Старт» → поставщику приходит запрос «Принять / Отклонить». /team — список, закрыть доступ.
  Сотрудникам приходят заявки на товары компании, как и поставщику; студии — уведомление о каждом добавлении;
- **заказчик**, **подрядчик проекта** и **работник подрядчика** — только по личной ссылке (заказчику и подрядчику — из «Студии»,
  работнику — от его подрядчика): кабинет «Мой проект», разговоры, документы, суммы работ — см. «Кабинеты: заказчик,
  подрядчик, работники подрядчика» ниже.

**Всё для студии — в «Студии»** (решено 24.10.2026): у разработчика и дизайнера слева от поля ввода — кнопка меню «Студия»
(заявки, проекты, деньги, контакты и доступ к боту, графики сайта). Кнопок под полем ввода больше нет: после обновления бота
им приходит сообщение «что где» и старые кнопки убираются. Кнопки под полем ввода («👥 Пользователи», «🤝 Партнёры»,
у разработчика «🌐 Сайт») появляются, только пока сайт не на домене и «Студию» открыть нельзя. Команды /users, /partners,
/site по-прежнему работают, если их набрать. Отметка «сообщение получено» ставится только после доставки (не доставилось —
бот попробует при следующем запуске), а разработчику после обновления бота приходит отчёт: кому сообщение
доставлено, кому нет и почему (например, «бот заблокирован — пусть откроет бота и нажмёт «Перезапустить»»).
Уведомления по-прежнему приходят в чат — с кнопкой, открывающей нужный экран «Студии»: новая заявка («📋 Открыть заявку
в «Студии»», адрес `/api/crm/app?lead=<номер>`), запрос доступа («👥 Открыть в «Студии»», `?tab=access`).
Под сообщением о новой заявке (дизайнеру, не партнёрам) — ещё «что это»: **📩 Заявка · 🤝 Реклама ·
🚫 Спам · 🙈 Игнорировать** (кнопки `ld:<номер>:<статус>`); выбранная отмечается «✓» и сразу видна в «Студии».
Отметка у одного не меняет кнопки в сообщении у другого — общий статус всегда в «Студии».

Доступ только по одобрению: человек нажимает «Старт», разработчику и дизайнерам приходит запрос с кнопками ролей
(для партнёра — выбрать или создать компанию). То же — в «Студии»: Контакты → **Доступ** (запросы, студия, партнёры по
компаниям с их товарами на сайте; принять, сменить роль, закрыть доступ, закрепить товары магазина — у разработчика).
Правила те же, что в чате (`Bot.access_action`): дизайнера назначает только разработчик, сотрудника поставщика — только
в компанию, где есть поставщик; адрес `/api/crm/access`.

Товар партнёра в магазине: в `content/pages/ru/shop/<товар>.json` поле `"partner": <номер>` (номер — в /partners).
Кнопка «Узнать цену» передаёт артикул (TDD-…); при выкладке `scripts/build_shop.py` собирает
`deploy/shop-products.json` (артикул → название, партнёр). Заявка на такой товар уходит людям партнёра,
а дизайнеру — уведомление «передана: …» (или «партнёр не подключён — передайте вручную»).

Проверка: `curl -s http://127.0.0.1:8095/api/lead/health`, журнал: `sudo journalctl -u dumskaya-lead -n 50`.

**Перезапуск бота без sudo.** Если при выкладке изменился только код бота и «Студии», `npm run deploy` перезапускает
сервис заявок без пароля: `/usr/local/lib/dumskaya/autodeploy restart` (`deploy/autodeploy.sh`, файл root, ставит
`server-setup.sh`) делает запись в `~/dumskaya/run/restart`, за ней следит `dumskaya-lead-restart.path` и перезапускает
только `dumskaya-lead`, потом ждёт до 40 секунд, пока новый процесс ответит. Пароль sudo нужен только для Caddy
и файлов сервисов. Журнал — `~/dumskaya/autodeploy.log`. (У `autodeploy.sh` есть и режим приёма архива от GitHub —
остался от автовыкладки 24.10.2026; ключа для него на сервере нет, поэтому он не используется.)

**Сторож сайта** (`deploy/site_monitor.py`, работает в том же сервисе, только в режиме live): раз в минуту
открывает https://dumskaya-design.com/ с сервера, как посетитель. 3 неудачи подряд — разработчику в бот
«🔴 Сайт не отвечает» с причиной и тем, что видно на сервере (Caddy не работает — значит, лежит и EuroExchange;
выкладка EuroExchange перезаписала Caddyfile; нет файлов сайта; кончилось место) и командой починки; раз в час —
напоминание; когда сайт снова отвечает — «🟢 Сайт снова работает». Сертификат HTTPS: меньше 14 дней до конца —
предупреждение раз в сутки. Команда `/site` в боте — состояние сейчас. Если сервер выключится целиком, этот
сторож молчит вместе с ним — для этого **сторож снаружи на GitHub** (`.github/workflows/site-watch.yml`,
`scripts/outside_watch.py`): примерно раз в 5 минут GitHub открывает сайт; не открывается ~10 минут — сообщение
от того же бота с пометкой, жив ли сам сервер (если жив — через ~30 минут: о коротком падении уже сообщил сторож
на сервере). Ничего не выкладывает. **Сейчас выключен** (включить: Actions → «Сторож сайта снаружи» → Enable workflow).
Нужен секрет репозитория `TELEGRAM_BOT_TOKEN` (Settings → Secrets and variables
→ Actions); проверка — Actions → «Сторож сайта снаружи» → Run workflow. GitHub выключает расписание, если
в репозитории 60 дней не было коммитов (пришлёт письмо) — тогда включить снова там же, в Actions.

**Посетители сайта** (`deploy/site_stats.py`, работает в том же сервисе, только в режиме live): считает посетителей
по журналу Caddy (`/var/log/caddy/dumskaya.log` и сжатые части рядом) — без скриптов слежения и без cookie,
сайт не замедляется, согласие не нужно. Посетитель — браузер (не робот, не предзагрузка), уникальность — IP + браузер
за день, только в памяти; за неделю — сумма по дням. **Сканеры, назвавшиеся браузером, отсеиваются** (`is_robot`):
кто запросил несуществующий адрес админки или служебного файла (`/login`, `/console`, `/dashboard`, `.env`, `wp-…` — список
`PROBE`, только при ответе 404) или открыл 10 страниц за 15 секунд — не посетитель ни в «1 час», ни в итогах
(в итогах дня — счётчик `bots`). Ещё роботом считается тот, кто **не загрузил ни оформления, ни фото** (`/_astro`, `/img`)
и **не прислал время на странице**: без заголовков перехода браузера (`Sec-Fetch-*`) — сразу, с ними — если через 30 минут
после последней страницы времени так и нет (вернувшийся посетитель берёт оформление из кэша, но время присылает).
Признак «нет ни оформления, ни заголовков перехода» действует и для старых дней; «30 минут без времени» — только
с момента, когда страницы начали присылать время (первая запись `times.jsonl`). При смене правил подсчёта (`STATS_VERSION`) дни, которые журнал ещё помнит, пересчитываются сами. Итоги дней — `~/dumskaya/stats/<дата>.json` (только цифры, без IP),
**хранятся бессрочно** (решено 24.10.2026: смотреть динамику за год и всё время после важных изменений на сайте).
Статистика смотрится **только в графиках**: кнопка меню «Студия» слева от поля ввода → вкладка «Сайт» (у разработчика
и дизайнера; вверху графиков — «← Студия») — мини-приложение Telegram (`deploy/stats_app.html`, отдаёт сервис заявок
по `/api/stats/app`), периоды
«1 час», «24 часа», 7 / 30 / 90 дней, «Год», «Всё время» (выбранный запоминается на телефоне). Время в приложении — по часам телефона того, кто смотрит.
- **1 час** — каждый посетитель отдельно (заходы, где что-то происходило за последний час): страна, регион и город по IP,
  устройство, система, браузер, язык браузера, откуда пришёл (Referer, а без него — метки gclid, fbclid, utm_source),
  страницы по порядку со временем открытия и временем на каждой, нажатия на контакты и заявка — у той страницы, где были;
  «на сайте» — последнюю страницу ещё не закрыли; «ранее за сутки» — сколько было заходов до этого. Обновляется само раз в минуту.
  IP-адреса в приложение не отдаются. Строится на лету из журнала за сутки (`web_live`), ничего не сохраняет.
- **24 часа** — те же плитки и карточки, что у дней, но графики по часам (текущий час — полая точка) и сравнение
  с предыдущими сутками; посетители за сутки — без повторов (меньше суммы по часам).
- **7 / 30 / 90 дней** — посетители по дням, просмотры, заявки, нажатия, языки, источники, устройства, страницы,
  робот Google, 404, таблица.
- **Год** — 52 недели и текущая, по неделям (сумма по дням), сравнение с предыдущими 52 неделями. **Всё время** — с первого
  дня данных, по неделям, а когда данных больше двух лет — по месяцам, без сравнения. Неделя или месяц, за которые есть
  данные не за все дни (начало статистики), отмечены в подсказке: «данные за 3 из 7 дн.» (`web_long`).

Данные (`/api/stats/data?p=1h|24h|7|30|90|365|all`) — только по подписи Telegram от этого бота и только разработчику и дизайнеру.

**Время на странице:** тот же скрипт на страницах, что и для нажатий, при закрытии или сворачивании страницы отправляет,
сколько секунд она была на экране (`{t: "time", p, s}` на `/api/hit`, не больше 120 сообщений за 10 минут с адреса).
Сервис пишет его в `~/dumskaya/times.jsonl`: время, страница, секунды и **обезличенный ключ посетителя** — хеш
IP + браузера с солью сервера (`~/dumskaya/stats/secret`, с сервера не уходит), сам IP не пишется; хранится 90 дней,
как журнал (чистится раз в день). По ключу время связывается с просмотрами из журнала. Нажатия на контакты в `hits.jsonl`
тоже получают этот ключ. В «1 час» — время на каждой странице (нет сообщения — «≈» до открытия следующей), в 24 часа /
7 / 30 / 90 дней — плитка **«Среднее время на сайте»** (на посетителя, только по тем, чьи страницы прислали время;
страница дольше 5 минут считается за 5 — дальше это забытая на экране вкладка; в карточке «1 час» — «больше 5 мин»), строка в подсказке графика и **«в среднем … на странице»** у популярных
страниц (когда время по странице пришло хотя бы 3 раза). В итогах дня — `time_total`, `time_visitors`, `page_time`.

**Город по IP** (`deploy/geo.py`): база DB-IP «IP to City Lite» (CC BY 4.0, указано внизу «1 час») — файл
`~/dumskaya/geo/dbip-city-lite.mmdb` (~130 МБ) на самом сервере, адреса никуда не отправляются. Сервис скачивает
выпуск сам (~60 МБ раз в месяц, в первые дни месяца), проверяет и только потом подменяет; нет места или не скачалось —
работает со старой базой, повтор через 6 часов. Первый раз база появляется через минуту-две после запуска сервиса.
Страна — по-русски из базы, регионы и частые города — по-русски из `deploy/geo_names_ru.json` (остальные латиницей,
дописывать туда же). Проверка с сервера: `python3 ~/dumskaya/deploy/geo.py 8.8.8.8`, скачать сейчас — `--update`. Каждый день в 9:00 разработчику — одна строка за вчера (по понедельникам и за неделю) с кнопкой
«📈 Графики»; текстовых отчётов и команды /stats нет (решено 24.10.2026). Журнал открыт для чтения (`mode 0644`
в нашем файле Caddy, 10 частей по 10 МБ, старше 90 дней удаляются — `roll_keep_for 2160h`, так написано в политике
конфиденциальности); полный текстовый отчёт для проверки с сервера: `python3 ~/dumskaya/deploy/site_stats.py`.

**Нажатия на контакты:** скрипт на всех страницах (`src/layouts/Base.astro`, меньше 1 КБ) при нажатии на телефон, e-mail,
WhatsApp или Telegram отправляет `navigator.sendBeacon('/api/hit')` — тип и страницу; сервис заявок пишет их
в `~/dumskaya/hits.jsonl` (без IP; роботы, свои адреса и больше 20 нажатий за 10 минут с адреса не записываются).
В графиках — нажатия по типам и страницам, в «1 час» — у конкретного посетителя (это из памяти сервиса, без записи IP);
в Google Analytics (если принят cookie) — событие `contact_click`.

**Свои визиты не считаются:** в мини-приложении внизу — блок «Не считать нас в статистике» (только у разработчика;
дизайнеру он не показывается и сервер ему список не отдаёт): нажать дома на домашнем
Wi-Fi, и визиты с этого адреса (IPv4 — адрес, IPv6 — сеть /64) больше не попадают ни в посетителей, ни в заявки; в графиках
ни строкой, ни карточкой в «1 час» эти визиты в графиках не показываются (решено 24.10.2026). Кроме того, **адрес,
с которого разработчик или дизайнер открывает «Графики»**, сам считается своим на 3 часа до и после (IPv6 — сеть /64,
`~/dumskaya/stats/own_devices.json`, хранится 100 дней): так не видны свои визиты с телефона на мобильном интернете,
который в «Не считать нас» добавлять нельзя. Список — `~/dumskaya/stats/exclude.json`; после изменения дни, которые журнал
ещё помнит, пересчитываются. Сменился домашний адрес у провайдера — открыть графики дома и нажать ещё раз. Журнал открыт для чтения
(`mode 0644` в нашем файле Caddy, хранится 10 частей по 10 МБ); проверка с сервера: `python3 ~/dumskaya/deploy/site_stats.py`.

## Учёт проектов студии («Студия»)

Учёт текущих и прошлых проектов — для дизайнера студии, больше никому. Открывается кнопкой меню **«Студия»**
слева от поля ввода в боте (мини-приложение Telegram `deploy/crm_app.html`, адрес `/api/crm/app`; данные — только
по подписи Telegram от этого бота). Внизу пять вкладок: **Заявки**, **Проекты**, **Деньги**, **Контакты** (заказчики,
подрядчики, доступ к боту), **Сайт** (графики посетителей). В проекте с 24.10.2026 ещё: разговоры с заказчиками, подрядчиками и их работниками, группы, товары
заказчика, доп. услуги, несколько заказчиков и ссылки в их кабинеты — см. «Кабинеты: заказчик, подрядчик, работники подрядчика» ниже.

**У разработчика (решено 24.10.2026)** в «Студии» только **Сайт** (графики и сверху — работает ли сайт: то, что
показывала команда /site, адрес `/api/stats/site`) и **Доступ** (запросы, роли, партнёры, товары магазина): «Студия»
сразу открывает графики, в них ссылка «👥 Доступ к боту». Заявки, проекты, деньги, заказчики и подрядчики сервер
отдаёт только дизайнеру (`studio_user` в `crm_api.py`); фото, присланные разработчиком в чат, в проекты не сохраняются.

- **Заявки с сайта** (с 24.10.2026): каждая заявка с формы сайта сразу записывается в учёт (`leads` в `crm.db`; файл
  `~/dumskaya/leads.jsonl` по-прежнему пишется первым — как страховка). Статусы (решено 24.10.2026): пришла — «Новая»;
  **что это** — «Заявка», «Реклама, сотрудничество», «Спам», «Игнорировать» (в заявке и кнопками в сообщении бота);
  у настоящей заявки — **как идёт**: «В работе», «Стала проектом», «Закрыта» (повторное нажатие возвращает в «Заявка»).
  Реклама, спам и «игнорировать» не попадают во «Все» — у каждого своя кнопка в списке, она видна, когда такие есть;
  фильтры «Новые / Заявки / В работе / Все». Из заявки, ставшей проектом, рекламу или спам сделать нельзя.
  Число новых — на вкладке «Заявки». В заявке — имя, контакт с кнопками «позвонить / WhatsApp / письмо / Telegram», сообщение
  и перевод на русский, товар и кому передана (партнёру, ответственному за товары магазина), страница сайта, заметка, история.
  **«＋ Сделать проектом»** — одна форма: заказчик (новый из заявки или найденный в контактах по почте или телефону) и проект;
  заявка получает «Стала проектом» и ссылку на проект. Заявки из файла, которых нет в учёте, добавляются при запуске сервиса;
  при первом запуске пришедшие до «Студии» за последние 30 дней получают «В работе», старше — «Закрыта» (с пометкой);
  пробные заявки мастера настройки не показываются.
- **Удаление заявок:** «🗑 Удалить заявку» внизу заявки; в списке «Реклама», «Спам», «Игнор» — «🗑 Удалить все» сразу.
  Удалённая 30 дней лежит в «Удалённых» (кнопка в списке; «↩︎ Вернуть заявку»), потом имя, контакт, текст и заметки
  стираются и в учёте, и в истории изменений (ежедневная уборка, `purge_leads`). Сама строка остаётся отметкой — так
  заявка не вернётся из `leads.jsonl` при следующем запуске. Проект, сделанный из заявки, остаётся. Файл
  `~/dumskaya/leads.jsonl` (страховочная копия всех заявок) удаление не меняет.
- **Ответ письмом:** «✉️ Ответить письмом» в заявке (и ✉️ у контакта) открывает «Почту» с готовым письмом: адрес, тема
  и приветствие на языке страницы, с которой пришла заявка (RU, UA, EN, SK, DE), подпись «Ирина Думская / Irina Dumskaya,
  DUMSKAYA DESIGN» и её сообщение ниже. Ирина дописывает текст и отправляет со своего ящика — письмо остаётся
  в «Отправленных». Из Telegram ссылки `mailto:` открываются не везде, поэтому кнопка открывает в браузере страницу
  `/api/crm/mail`, а она — «Почту»; адрес и текст передаются после «#» и на сервер (и в журнал) не попадают.
Код: `deploy/crm.py` (база и расчёты), `deploy/crm_api.py` (адреса `/api/crm/*`), `deploy/crm_bot.py` (файлы через чат),
`deploy/fx.py` (курсы валют), `deploy/backups.py` (резервные копии). Всё в том же сервисе заявок, только стандартная библиотека Python.

- **Проект:** номер по внутреннему учёту (два проекта с одним номером не сохранятся), название, статус (в работе, на паузе,
  завершён, отменён), заказчик, город и страна, адрес, площадь, тариф, сумма договора в евро, даты начала и окончания, заметки.
  Список — поиск по номеру, названию, заказчику, городу и тарифу; «В работе / Завершённые / Все»; у каждого — сколько оплачено.
- **Операции проекта** (вся история, у каждой — кто и когда записал):
  **оплата заказчика** — сумма, валюта, дата, способ; **бонус** (откат) — от подрядчика проекта (с этапом или в целом)
  или от другого поставщика, фабрики (за что, от кого); **перепродажа** (студия — посредник) — что, у кого, закупка
  и продажа, каждая в своей валюте; доход — разница.
- **Подрядчики проекта и их этапы:** у подрядчика в проекте — этапы работ (кухня, шкафы, черновые, чистовые…):
  сумма заказа и **бонус студии** — процент (по умолчанию 10 %, меняется в ⚙︎), сумма или «неизвестно» (откат заранее
  не знали — потом записывается как полученный бонус). Кнопка «🎁 Отдал бонус» у подрядчика подставляет его долг.
  **Долг подрядчика** = бонусы с его этапов − бонусы, которые он уже отдал в этом проекте; считается в валюте его этапов
  (оплата в той же валюте закрывает долг ровно, без хвостов от курса), рядом — в евро. Полученный бонус сразу идёт
  в доход проекта. Долг виден в проекте, в карточке подрядчика (по всем проектам) и на вкладке «Деньги».
  Подрядчика с этапами или бонусами нельзя убрать из проекта, пока они есть; удалённый этап оставляет полученные бонусы за подрядчиком.
- **Валюты (решено 24.10.2026):** договор и баланс проекта — в евро; операции и этапы — в евро, гривне, долларе или злотом.
  В евро пересчитывается по курсу на дату операции: Европейский центробанк, для гривны — Нацбанк Украины. Курс виден у операции («курс НБУ 10.10.2026: 1 € = 50,4350 ₴»); если платили по другому курсу — галочка
  «Ввести курс вручную». Курсы хранятся в `~/dumskaya/fx.db`; в выходные ЕЦБ курс не публикует — берётся последний до этой даты.
  Проверка с сервера: `python3 ~/dumskaya/deploy/fx.py UAH 2026-10-20`.
- **Деньги в проекте:** договор, оплачено, остаток (или переплата), доп. доход (бонусы и наценка) и весь доход по проекту.
  Баланс = договор − оплаты заказчика. Доход студии = оплаты + полученные бонусы + наценка на перепродажах.
- **Вкладка «Деньги»:** месяц, квартал, год, всё время — доход и из чего он сложился, сколько ещё должны заказчики
  по активным проектам, **сколько должны подрядчики** (по подрядчикам и проектам, кроме отменённых), доход по месяцам
  (12 месяцев), по городам, по тарифам, бонусы — от кого, самые доходные проекты. Считается по дате операции.
- **Контакты:** заказчики (телефон, почта, мессенджер, как удобнее связаться, город, заметки — кнопки «позвонить»,
  WhatsApp, письмо) и подрядчики по видам работ (прораб, мебельщик, шторница, кондиционерщик, двери, окна и др.).
  Подрядчик привязывается к проекту с видом работ. Тарифы, виды работ и категории бонусов меняются в ⚙︎ на вкладке «Проекты».
- **Файлы проекта:** «Обмерный план», «Опросник» (заполненный заказчиком), «До», «Визуализации», «Документация», «После»,
  «Другое». Добавить — в проекте «＋ Добавить в …» (до 60 МБ файл, превью для фото делается на телефоне; на компьютере —
  ещё перетащить файлы в блок или вставить из буфера ⌘V / Ctrl+V) или **прислать фото и документы боту в чат**: бот спросит, в какой проект и что это;
  альбом или несколько файлов подряд — один вопрос на все. Telegram даёт боту скачать файл до 20 МБ; больший остаётся
  в Telegram, в «Студии» его можно прислать себе в чат. Любой файл проекта — «Открыть» (ссылка действует 12 часов),
  «Прислать в чат», перенести в другую категорию, удалить. Файлы — `~/dumskaya/crm/files`; если на диске сервера меньше
  2 ГБ свободно, новые не принимаются (сервер общий). HTML, SVG и другие «активные» типы отдаются только как скачивание.
  Удалённый файл 30 дней лежит в корзине `~/dumskaya/crm/trash/<дата>/` (вернуть — переложить на место и добавить заново).
- **Удобство:** интерфейс подогнан под iPhone Pro Max (экран 440 точек): крупный текст и кнопки, «Сохранить» — кнопка
  Telegram внизу (на iPhone она над клавиатурой), свайп вниз не сворачивает «Студию», с открытой формой Telegram переспросит,
  прежде чем закрыть. В Telegram на Mac и Windows — то же окно; Esc закрывает просмотр, ⌘/Ctrl+Enter сохраняет форму.
- **Размер текста** (⚙︎ → «Размер текста»: обычный, крупный ×1,25, очень крупный ×1,5) — свой у каждого, хранится на сервере
  (`ui:size:<Telegram ID>` в базе бота, адрес `/api/crm/ui`) и действует на всех его устройствах — в «Студии» и в графиках сайта.
  **У дизайнера по умолчанию «Крупный»** (решено 24.10.2026: у Ирины плохое зрение), у разработчика — обычный. В крупных
  размерах ещё и контрастнее: второстепенный текст почти чёрный (в тёмной теме — почти белый), рамки полей и кнопок толще,
  кнопки «Оплата / Бонус / Перепродажа» и плитки графиков — по одной в строку, чтобы ничего не обрезалось.
  Размер текста в самом чате с ботом задаёт Telegram (на iPhone: Настройки → Оформление → Размер текста).
- **Версия** — мелко внизу «Студии» и графиков: «Студия · версия a1b2c3d · 24.10.2026 15:10 · Мак» — коммит, когда
  и откуда выложено («+ правки» — выложено с незакоммиченными изменениями).
  Файл `deploy/VERSION` пишет `npm run deploy` (в git его нет), читается при запуске сервиса — то есть показывает код,
  который работает сейчас. Нет файла — «код 1a2b3c4» (отпечаток файлов). Так можно проверить, дошло ли обновление:
  закройте и снова откройте «Студию».
- **Удаление:** проект с операциями или файлами не удаляется — ставится статус «Отменён». Все изменения пишутся в историю
  проекта («История изменений» внизу проекта).

**Копии** — раздел «Резервные копии» ниже. Данные заказчиков в учёте — только на сервере и в резервных копиях
(на сервере и у разработчика в Telegram); на сайт, в фото и чертежи портфолио они не попадают.

## Резервные копии (с 24.10.2026: на сервере и в Telegram, не на Мак)

Код — `deploy/backups.py` (в сервисе заявок, раз в минуту проверяет, пора ли), проверка — `python3 scripts/tests/test_backups.py`.

1. **На сервере, каждую ночь** (первые минуты после полуночи по Братиславе) — архив
   `~/dumskaya/backups/dumskaya-data-ГГГГ-ММ-ДД.zip` (права 600): база «Студии» `crm.db` (проекты, деньги, заказчики,
   кабинеты, переписка, список файлов), база бота `bot.db`, курсы `fx.db`, заявки `leads.jsonl`, статистика сайта
   (`stats/`, `hits.jsonl`, `times.jsonl`) и настройки сервиса `lead.env`. Базы копируются средствами SQLite — целостно,
   не останавливая сервис. **Хранятся 7 последних дней**, старые удаляются сами (вместе с прежними копиями `crm-…db`).
2. **В Telegram разработчику, без звука** — тот же архив, но **без `lead.env` и соли статистики `stats/secret`**: токен бота,
   ключи и пароли в Telegram не уходят. Бот не может писать в «Избранное» — копии приходят в чат с ботом,
   любую можно переслать в «Избранное». Не отправилось — следующая попытка через час, после трёх неудач подряд
   бот пишет разработчику. Архив больше 50 МБ Telegram от бота не примет — тогда бот скажет об этом, копия останется на сервере.
3. **Файлы проектов — в Telegram, каждый один раз**: новые файлы («Студия», кабинеты, переписка) архивами
   `dumskaya-files-ДЕНЬ-NN.zip` до 45 МБ, внутри понятные имена — `12 Квартира в Братиславе/Визуализации/00045-гостиная.jpg`
   (число перед именем — номер файла в «Студии», по нему файл возвращается на место). Файл 45–50 МБ — отдельным
   документом; файл, который хранится только в Telegram (больше 20 МБ), — пересылкой; больше 50 МБ — только на сервере
   (бот один раз присылает их список). За минуту — одна отправка, поэтому первые копии старых файлов идут постепенно.
   Свободно на сервере меньше 2 ГБ — архив файлов не собирается (сервер общий с EuroExchange).
   На сервере файлы отдельно не копируются: они лежат в `~/dumskaya/crm/files`, удалённые — 30 дней в корзине.
4. **Hetzner Backups** — снимок всего сервера раз в сутки, 7 последних (панель Hetzner: сервер → Backups) — если сервер
   сломается целиком.

Архив данных сейчас (например, перед рискованной правкой) — на сервере: `python3 ~/dumskaya/deploy/backups.py --now`.

**Вернуть базы** (из копии на сервере за нужный день) — на сервере (`ssh eurox`):
```bash
sudo systemctl stop dumskaya-lead && python3 ~/dumskaya/deploy/backups.py --restore-data ~/dumskaya/backups/dumskaya-data-2026-10-24.zip; sudo systemctl start dumskaya-lead
```
Возвращаются `crm.db`, `bot.db`, `fx.db`, заявки и статистика; нынешние файлы перед заменой сохраняются в
`~/dumskaya/restore-ВРЕМЯ/`, журналы старых баз (`-wal`, `-shm`) убираются. `lead.env` возвращается, только если его нет
(в копии из Telegram его нет — тогда ключи снова вписывает мастер: с Мака `npm run leads`). Копию из Telegram сначала
сохранить на Мак и отправить на сервер: `scp ~/Downloads/dumskaya-data-2026-10-24.zip eurox:dumskaya/backups/`.

**Вернуть файлы проектов** — архивы `dumskaya-files-…zip` положить на сервер и на сервере:
`python3 ~/dumskaya/deploy/backups.py --restore-files ~/dumskaya/backups/dumskaya-files-*.zip` — каждый файл ложится
на своё место, если его там нет (уже лежащие не трогаются); пропавшие миниатюры сбрасываются и делаются заново.

## Кабинеты: заказчик, подрядчик, работники подрядчика; разговоры и документы (с 24.10.2026)

Заказчики проекта (обычно до 5 человек, не больше 10), подрядчики и работники подрядчиков получают в боте студии свой
**кабинет** — кнопка меню **«Мой проект»** слева от поля ввода (мини-приложение `deploy/portal_app.html`, адрес `/api/portal/app`).
Код: `deploy/crm_portal.py` (кто что видит, приглашения, бригады, разговоры, документы, напоминания), `deploy/portal_api.py`
(адреса `/api/portal/*` — их же использует «Студия» для разговоров), `deploy/portal_bot.py` (всё в чате бота, тексты на пяти языках).
Проверка: `python3 scripts/tests/test_portal.py` (временные базы, Telegram подменён; права, разговоры, документы, бригада, наблюдатель).

- **Как попадают в кабинет.** У каждого — личная ссылка `t.me/<бот>?start=pj_…` на 14 дней (для одного человека; новая отменяет
  прежнюю неиспользованную). Ирина выбирает язык сообщения (RU, UA, EN, SK, DE) и отправляет готовый текст в Telegram, WhatsApp,
  письмом или копирует. Человек открывает ссылку и нажимает «Старт» — Telegram привязан, Ирине приходит «✅ подключился».
  - **Заказчик** — из проекта: блок «Заказчики» → «🔗 Ссылка в бот».
  - **Подрядчик** (руководитель: прораб, хозяин мебельной фабрики…) — **один раз** (решено 24.10.2026): «Контакты» → «Подрядчики» →
    карточка → «Кабинет в боте» → «🔗 Ссылка в бот» (или из проекта). Дальше он сам видит все проекты, куда его добавят
    (о новом — сообщение). Роль в боте — «Подрядчик проекта»; партнёры (поставщики, мебельщики) остаются в своей роли.
  - **Работник подрядчика** (технолог, установщик, плиточник…) — ссылку даёт сам подрядчик: кабинет → «Бригада» → «＋ Работник» →
    «🔗 Ссылка в бот» (текст — от имени подрядчика). Подключённый работник **не попадает во все проекты**: подрядчик отмечает,
    кого отправляет на этот объект (в проекте — «Бригада на этом объекте», в «Бригаде» — объекты у каждого). Ирина тоже может
    добавить работника и отметить его на объекте (в проекте у подрядчика — «Бригада на объекте»). Роль в боте — «Работник подрядчика».
  - «Закрыть кабинет» отвязывает Telegram. Доступ к боту закрывается, когда кабинета не осталось: у заказчика — нет проектов;
    подрядчик и работник без текущих объектов кабинет не теряют (их подключают один раз), закрывается — если Ирина закрыла
    кабинет, подрядчик убрал работника из бригады или подрядчика удалили. Дизайнер, открывший ссылку, её не тратит.
- **Что кто видит** (сервер отдаёт только перечисленное — `Portal.client_view / contractor_view / worker_view`):
  - **заказчик** — проект (пакет, город, площадь), сколько осталось оплатить (договор, доп. услуги, товары), следующий платёж, историю
    оплат, доп. услуги, товары (цена, авансы, поставка), документы студии (все разделы, кроме «Другое»), документы подрядчиков,
    открытые ему, «Согласовано» (вложения разговоров, которые Ирина открыла заказчику), подрядчиков с контактами и суммами работ.
    **Не видит** бонусы студии, закупки, поставщиков, наценку, заметки студии, работников подрядчиков и «Разработчик ПО».
  - **подрядчик** — проект (адрес), контакты заказчиков, документацию студии (обмерный план, до, визуализации, документация, после),
    документы своей бригады, свой подряд (этапы, вознаграждение студии — по умолчанию 10 %, сколько передал), свою бригаду.
  - **работник** — объект **без денег** (ни суммы проекта, ни вознаграждения студии, ни контактов заказчика), контакты своего
    руководителя и студии, документацию студии, документы бригады, открытые бригаде.
  - **Ирина** — всё: в «Студии» в проекте — разговоры, подрядчики с бригадами, все файлы с подписью «кто видит».
- **Документы подрядчиков и работников** (раздел «От подрядчиков»): фото выполненных работ (повешенные шторы, поставленные окна,
  двери…) и техническая документация — кабинет → «Документы» → «＋ Фото или документ», подпись и **кто видит**:
  у подрядчика — «Заказчик, студия и моя бригада», «Студия и моя бригада», «Только студия»; у работника — «Руководитель и студия»
  (заказчик не видит), «Вся бригада и студия», «И заказчик тоже». Свой документ можно переименовать, поменять «кто видит», удалить;
  подрядчик — и документы своих работников. Ирине — сообщение о каждом новом документе; подрядчику — о документах его работников;
  заказчику — если документ открыт ему. Ирина в просмотре файла может открыть его заказчику или скрыть («Заказчик: да / нет /
  по разделу»), а у своих файлов — и подрядчикам с бригадами.
- **Разговоры** (решено 24.10.2026). У проекта несколько разговоров, каждый со своими участниками:
  - «Заказчики» — Ирина и заказчики проекта;
  - «Заказчик ↔ подрядчик» — заказчик пишет любому подрядчику проекта (руководителю, **не работникам**). Ирина видит и получает
    такие сообщения **без звука** («вы видите, но не участвуете»); ответит — вступает в разговор, дальше — со звуком.
    Заказчик и подрядчик видят пометку, что Ирина видит разговор;
  - «Студия ↔ подрядчик» и «Студия ↔ работник» — Ирина пишет любому подключённому («Разговоры» → «✏️ Написать…» или 💬 у человека).
    **Переписку студии с работником видит его руководитель** (только читает, копии — без звука): хозяин мебельной фабрики видит
    общение Ирины с его технологом, потом с установщиками;
  - **группы** — Ирина собирает сама: «Разговоры» → «👥 Группа» → название и участники (подрядчик и его работники; работник,
    которого ещё не отметили на объекте, отмечается сам). Участникам — сообщение на их языке; руководитель видит группы, где его
    работники. Заказчик групп не видит. Пока в группе нет сообщений, её можно удалить.

  открывает заказчику кнопкой «👁 Показать заказчику» у вложения (или галочкой «Файл увидит и заказчик» при отправке) — у заказчика
  он появится в «Документах» → «Согласовано».

  бот спросит, к какому); ответом (свайп влево) — в тот разговор, на сообщение которого отвечают (в чужой — «только чтение»).

  до 20 МБ. Данные — `threads`, `thread_members`, `thread_read`, `messages` в `crm.db`; вложения — раздел «Из переписки».

## Магазин: товары фабрик

Фабрики — `content/shop/manufacturers.json` (название, страна, контакты, **за каким партнёром закреплена**,
файл каталога). Каталог фабрики — `content/shop/catalog/<фабрика>.json`: коллекции (линия, дизайнер, отделки)
и товары (артикул сайта, артикул изготовителя, коллекция, тип, страницы каталога). Цен нет — «Узнать цену».

**Артикулы сайта** не совпадают с артикулами изготовителя и не выдают фабрику:
`DL-<тип><номер>` для света — `S` подвесной, `C` потолочный (встраиваемый, трековый, споты), `W` бра,
`T` настольная лампа, `F` торшер, `G` встраиваемый в пол / ландшафтный;
`DF-<тип><номер>` для мебели — `S` диваны, `A` кресла, кушетки, пуфы, `C` стулья, табуреты, скамьи,
`T` столы, письменные столы, консоли, `K` журнальные и прикроватные столики, `B` кровати, изголовья, матрасы,
`H` хранение (шкафы, стеллажи, комоды, буфеты, системы, мебель для ванной), `D` ковры, зеркала, ширмы, текстиль,
аксессуары, `E` кухни и кухонные модули.
Номер — четыре цифры, уникален по всему сайту (по телефону достаточно «1310»); у каждой фабрики свой диапазон:

|---|---|

| OLEV | 3000–3399 |
| Delta Light | 3400–4699 |
| Baxter | 5000–5599 |

## Включение домена

Когда DNS домена указывает на сервер (A `62.238.124.237`, AAAA `2a01:4f9:c015:6ee0::1`, www → CNAME на домен):

```bash
ssh -t eurox 'sudo bash ~/dumskaya/deploy/server-setup.sh live'
```

Caddy сам получит HTTPS-сертификат. Затем в Search Console отправить `https://dumskaya-design.com/sitemap.xml`.

## Если на сервере что-то пошло не так

```bash
ssh -t eurox 'sudo bash ~/dumskaya/deploy/server-doctor.sh'
```

Показывает состояние Caddy и причину ошибки, отключает сайт от Caddy (свою строку в Caddyfile и файл сайта)
и проверяет, что остальные сайты на сервере отвечают.

**Сосед по серверу — EuroExchange.** Основной `/etc/caddy/Caddyfile` принадлежит ему: его выкладка
(`/opt/eurox0003/deploy.sh`) перезаписывает файл целиком из репозитория eurox0003. Наш сайт подключается
строкой `import sites/*.caddy` в том Caddyfile (сайт — файл `/etc/caddy/sites/dumskaya.caddy`).
Если строки нет, `server-setup.sh` дописывает свою, а `npm run deploy` замечает пропажу и подключает сайт снова;
в конце выкладка проверяет, что https://dumskaya-design.com отвечает.

## Новый проект в портфолио

Фото (уменьшенные до 2400 px по длинной стороне, без EXIF) кладутся в `assets/photos/<проект>/` и попадают в git;
при выкладке `scripts/images.mjs` делает из них WebP. Для каждого фото — запись в `content/images.json`
(файл, размеры, описания ru/ua/en; на словацком и немецком описания фото берутся из памяти переводов),
имя файла на сайте — в `content/image-names.json`, помещение —
в `content/image-rooms.json` (порядок фото: гостиная-кухня, спальня, ванная, детская, постирочная, прихожая, санузлы).
**Имена файлов — описательные** (с октября 2026): исходники — `assets/photos/<город>-<площадь>m/01-living-room-kitchen.jpg`,
имя на сайте — что на фото, объект, город, номер: `living-room-kitchen-apartment-bratislava-127m-01`,
`floor-plan-apartment-bratislava-127m`; английские слова, латиница, через дефис, до 80 знаков, без имён заказчиков.
Уже выданные имена не меняются (по ним фото знает Google); `scripts/image_names.py` только дописывает имена
забытым новым фото (помещение по `image-rooms.json` + адрес страницы) и прежние не трогает.
Страница — `content/pages/ru/<адрес>.json` (тип `project`), карточка и «штамп» (объект, площадь, город, работы,
статус) — `content/projects.json`, первой в списке = первой в портфолио. Планировку с листа дизайн-проекта
показывает блок `{"type": "figure", "image": {...}, "caption": "..."}` — после текста, перед фото.
Листы технической документации — отдельная секция: заголовок «Пример технической документации, разработанной
в рамках дизайн-пакета «…»» и галерея с `"docs": true` (показывается после фото отдельным блоком под этим
заголовком; в `image-rooms.json` такие листы — `D`). Листы — целиком, PNG 2400 px; в штампе листа не должно быть
данных заказчика (имя, адрес).
Видео с YouTube — блок `{"type": "video", "youtube": "<id ролика>", "poster": "<id фото проекта>"}` сразу после
заголовка; превью — фото проекта, плеер (youtube-nocookie.com) загружается только по нажатию.
Товары магазина на странице — `{"type": "products", "items": ["/shop/...", ...]}` (русские адреса, на других
языках — те же товары на языке страницы).
Пример — квартира 127 м² в Братиславе (`assets/photos/bratislava-127m/`). Затем перевод (ниже) и выкладка.

## Переводы (UA, EN, SK, DE)

Тексты страниц пишутся на русском (`content/pages/ru/`), остальные версии собираются из них:
структура, фото и блоки те же, тексты — из памяти переводов `content/i18n/tm-{ua,en,sk,de}.json`
(русская строка → перевод), ссылки автоматически ведут на страницы того же языка.
Адреса, title и description украинских и английских страниц при сборке не меняются.

**Словацкая (`/sk`) и немецкая (`/de`, австрийский вариант) версии** — с 23.10.2026. Глоссарий, местные поисковые
формулировки и типографика — в `scripts/i18n/GUIDE.md`, шаблонные обороты SK/DE — в `content/TEXT_STYLE.md`.
- Какие страницы есть на SK/DE — решает `alternates.sk` / `alternates.de` у русской страницы. Не переведены
  (адресованы другим рынкам): посадочные Варшавы, Украины, США, Праги и Испании; страница «Германия» — только DE.
- Адреса, title и description — в `content/i18n/meta-sk.json` и `meta-de.json` (ключ — русский адрес; адрес — поисковая
  фраза на языке страницы: `/sk/dizajn-interieru-bratislava`, `/de/innenarchitekt-wien`). После правки этих файлов
  (или новой страницы) — `python3 scripts/i18n/apply_meta_new_langs.py` с файлами `{"/ru-адрес": {"path", "title",
  "description"}}`: проверит длины и адреса, проставит `alternates` русским страницам и проектам, создаст страницы
  магазина и меню SK/DE в `site.json`. Выданные адреса SK/DE не меняем — только через редирект.
- Ссылка на страницу, которой на этом языке нет, при сборке становится обычным текстом (кнопка и карточка — убираются).
- **Телефоны**: на словацких страницах — только +421 918 17 77 85, на немецких — только +43 677 614 30 187 (шапка,
  меню, подвал, «Контакты», тексты страниц, разметка). Номера в текстах заменяет `assemble.py`, проверяет `check_site.py`.
  Мессенджеры (WhatsApp, Telegram) — на словацком номере на всех языках.

После правки русских текстов:
```bash
python3 scripts/i18n/extract.py            # новые строки → пакеты i18n-work/<lang>-NN.json
# перевести пакеты (правила и глоссарий: scripts/i18n/GUIDE.md), ответы — i18n-work/out-<lang>-NN.json
python3 scripts/i18n/check_batch.py i18n-work/ua-01.json
python3 scripts/i18n/assemble.py --import   # добавить переводы в память и собрать страницы
for l in ua en sk de; do python3 scripts/i18n/check_tm.py $l; done
```
